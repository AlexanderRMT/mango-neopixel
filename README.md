# neopixel

A small bare-metal driver for WS2812 / NeoPixel addressable LEDs on the
Mango Pi MQ-Pro (Allwinner D1, RISC-V).

Any GPIO pin can be used as the data line — the driver resolves the pin to its
GPIO data register at runtime, so nothing has to be recompiled or hardcoded to
change pins. Multiple independent strips on different pins are supported.

The interface is loosely modeled on the Adafruit NeoPixel library, but the code
here is not derived from it.

## Status

Working and in use, but early. The bit timing is generated by a hand-written
assembly delay loop, which means `neo_show()` blocks for its whole duration.
Replacing that with the D1's hardware LEDC peripheral is the main planned
change — see [Roadmap](#roadmap).

## Requirements

This driver is **not standalone**. It is written against the CS107E `libmango`
support library and needs its headers and lib at build time:

| Header | Used for |
| --- | --- |
| `gl.h` | `color_t`, the 32-bit `0xXXRRGGBB` color type |
| `gpio.h` | `gpio_id_t`, `gpio_set_output` |
| `timer.h` | `timer_delay_us` for the latch delay |
| `malloc.h` | allocating the strip and its pixel buffer |

Toolchain: `riscv64-unknown-elf-gcc` / `-as`, built for `-march=rv64im -mabi=lp64`.

## API

```c
#include "neopixel.h"
```

#### `neopixel_t *neo_new(gpio_id_t data_pin, unsigned int num_pixels, uint8_t brightness)`

Allocates a strip of `num_pixels` on `data_pin`, with a global `brightness` of
0–255. The pin is configured as an output on the first `neo_show()`.

#### `void neo_set_pixel(neopixel_t *strip, unsigned int i, color_t c)`

Sets pixel `i` to color `c` in the in-memory buffer. Nothing reaches the strip
until `neo_show()`. Out-of-range indices are ignored rather than treated as an
error.

#### `void neo_set_brightness(neopixel_t *strip, uint8_t brightness)`

Sets the global brightness, 0–255, applied to every channel when the strip is
shown. Scaling happens at send time, so the stored colors are never degraded by
lowering the brightness and raising it again.

#### `void neo_show(neopixel_t *strip)`

Pushes the buffer out to the strip and holds the line low long enough to latch.
This is the only function that touches hardware, and it blocks for roughly
30 µs per pixel plus a 55 µs latch delay.

### Example

```c
#include "neopixel.h"
#include "gl.h"

#define NUM_PIXELS 12

void main(void) {
    neopixel_t *ring = neo_new(GPIO_PE17, NUM_PIXELS, 255);

    for (int i = 0; i < NUM_PIXELS; i++) {
        neo_set_pixel(ring, i, i % 2 == 0 ? GL_BLUE : 0);
    }
    neo_show(ring);
}
```

## Building

There is no Makefile in this repo yet. To build by hand, with `CS107E` pointing
at your support-library install:

```sh
riscv64-unknown-elf-gcc -march=rv64im -mabi=lp64 -I$CS107E/include \
    -c neopixel.c -o neopixel.o
riscv64-unknown-elf-as  -march=rv64im -mabi=lp64 neo_timing.s -o neo_timing.o
```

`neo_timing.s` must be assembled and linked in — `neopixel.c` only declares
`send_bit`, so leaving the assembly out gives an undefined-reference error at
link time.

Then either link both objects into your program directly, or bundle them:

```sh
riscv64-unknown-elf-ar rcs libneopixel.a neopixel.o neo_timing.o
```

## Roadmap

- **LEDC backend.** The D1 has a dedicated LED controller that generates the
  WS2812 waveform in hardware. Moving to it would stop `neo_show()` from
  busy-waiting and remove the hand-tuned assembly timing entirely.
- **More Adafruit-style helpers** — `fill`, HSV color conversion, rainbow/wheel.
- **Decouple `color_t` from `gl.h`**, so the driver does not pull in a whole
  graphics library for one typedef.
